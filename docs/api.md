# NDCConnect API (v1)

The contract between the React web app and Django (spec 15). The machine-readable version is `docs/openapi.json`
(OpenAPI 3.1, generated by drf-spectacular). This page holds the conventions, the error and rate-limit catalogues, and
how to add an endpoint.

## Conventions

- **Base path** `/api/v1/`. Lower-case, hyphenated, plural nouns; trailing slash. `/me/…` acts on the signed-in person,
  `/admin/…` needs an admin role, `/campaign/…` a candidate-scoped role, `/webhooks/…` a provider signature.
- **Auth** `Authorization: Bearer <Clerk session token>`. Django verifies the token itself (signature, expiry, authorised
  party) and refuses deactivated accounts. No cookies, so no CSRF surface.
- **Methods** `GET` reads; `POST` creates or runs an action; `PUT` replaces (images, details); `PATCH` partial update;
  `DELETE` removes. `PUT`, `PATCH`, `DELETE` are idempotent.
- **JSON** in and out (multipart only for file uploads). Dates are ISO 8601 with offset; money is integer kobo.
- **Errors** one envelope:
  `{"error": {"status": 400, "code": "validation_error", "message": "…", "fields": {…}, "request_id": "9f2c…"}}`.
  `message` is safe to show. 429 adds `retry_after` and a `Retry-After` header.
- **Request IDs** every response has `X-Request-ID` (kept from the proxy when valid). Error messages for 5xx include
  "Reference: <first 8 characters>"; support finds the log line by it.
- **Pagination** `?page=N`, 20 per page unless a spec says otherwise:
  `{"count", "next", "previous", "results"}`. A page past the end is `404 not_found`.
- **Filters** query parameters named after the field. An unknown value for a choice filter is `400 invalid_filter`;
  unknown parameter names are ignored. `?q=` is 2–100 characters and never logged. Ordering, where offered,
  is `?ordering=field` / `-field` from an allow-list (`apps/core/filters.py`).
- **Versioning** v1 changes are additive only. Removing or renaming a field or endpoint, changing a type, or making an
  optional field required needs a parallel endpoint or `/api/v2/`, and an entry in `docs/api-changes.md`
  (`manage.py api_compat` enforces this in CI).

## The schema

- Regenerate after any API change:
  `DJANGO_SETTINGS_MODULE=config.settings.schema python manage.py spectacular --format openapi-json --file docs/openapi.json --validate --fail-on-warn`
- CI fails when the committed file differs from the generated one, and when `api_compat` finds an unexplained
  breaking change.
- Each operation carries `x-permissions` (who may call it), `x-error-codes` (catalogued codes it can return) and
  `x-rate-limit` (its throttle scopes). Error codes are those the view's module raises plus the standard ones for its
  permissions, so the list is a superset.
- **Typed responses.** Endpoints built on serializers, and every endpoint added since unit 15, have typed response
  schemas. Older hand-built views are published as an open object with `x-untyped: true`; `docs/openapi-untyped.txt`
  lists them, and a test fails if a new one appears. Type them (with `@extend_schema`) as each area is next changed.
- Live schema: `GET /api/v1/schema/` (system admins in production; anyone in development). Swagger UI
  (`/api/v1/schema/docs/`) and ReDoc (`/api/v1/schema/redoc/`) exist in development only.

## Adding an endpoint

1. Put the rule in the service layer; the view only parses, checks permissions and shapes the answer.
2. Use `IsSignedIn` (the default) or a stricter permission; add a throttle scope to `apps/core/throttling.py` and the rates.
3. Raise `ServiceError(message, code=…, status_code=…)` with a code from `apps/core/errors.py` (add new codes there).
4. Declare request and response shapes (`serializer_class` or `@extend_schema(request=…, responses=…)`), with an
   example for writes.
5. Sensitive actions: add the URL name to `SECOND_FACTOR` / `ANY_FACTOR` in `apps/access/security.py`.
6. External calls go through `apps/integrations/http.py`; side effects after commit go through `apps/core/outbox.py`.
7. Regenerate `docs/openapi.json`, then `npm run api:types` in the web app.
